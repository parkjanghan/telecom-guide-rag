# 1단계 완료 — 선택 주제를 반영한 검색어 생성

- 완료일: 2026-10-23 (Asia/Seoul)
- 범위: F2003의 선택 주제 문맥 전달 보완. 2~6단계는 실행하지 않았음.

## 변경 내용

1. 직접 선택한 주제 또는 자동 선별한 주제를 먼저 결정한다.
2. 검색어 생성 입력에 주제 ID·이름·설명·범위·서비스 유형·확인할 변수 이름을 전달한다.
3. 메타데이터는 탐색 문맥으로만 사용하며 정책 근거가 아니라고 명시한다. 변수 이름에서 사용자 값을 추측하지 않고, 현재 질문의 명시적 정보가 우선하도록 프롬프트를 보완했다.
4. 자동 선택 흐름도 동일한 검색어 생성 함수를 사용한다. 추가 모델 호출 없이 기존 두 호출의 순서만 조정했다.

현재 흐름: 질문·최근 대화 → 상담 주제 확정 → 선택 주제를 포함한 검색어 생성 → 공식 근거 검색 → 기존 답변 생성.

## 검증

- 기존54개 + 신규7개 = 자동 테스트61개 통과.
- 신규 회귀: 짧은 질문, 자동 선택 후 주제 전달, 복수 주제 중복 제거, 메타데이터 비근거 처리/경로 제외, 빈 주제 목록, 잘못된 주제, 잘못된 모델 출력.
- 원본 MD 1,426개 SHA-256 변경 없음.
- 실제 GMS는 검색어 생성과 로컬 문서 검색만 검증했다. 외부 크롤링·답변 생성은 이번 단계의 실험에서 실행하지 않았다. 아래 시간은 전체 상담 응답 시간이 아니다.

## 계획 점검

F2003에서 지적한 선택 주제 누락은 이번 단계에서 보완했다. 주제 설명을 사실 근거로 사용하지 않도록 제한했으며, 원래 선택된 주제의 근거 검색 범위는 유지했다.

실제4개는 개발 점검 사례이며 전체 상담 정확도를 보장하지 않는다. 전체 응답 성능·키/색인 누락·반복 수집·경계 조건 검증은4~5단계에 남겨둔다.

다음은2단계인 대표 근거 미연결2개 주제 조사와 서비스 노출 방식 정리다. 현재 결과로 계획 순서를 바꿀 이유는 없다.

## 적용 방법

실행 중인 서버는 Python 모듈을 이미 읽은 상태이므로 재시작해야 한다. 원본·설정·벡터 색인을 바꾸지 않아 재색인은 필요 없다.

Git Bash:

```bash
cd /c/SSAFY/workspace/telecom-guide-rag
powershell.exe -ExecutionPolicy Bypass -File ./run-chat.ps1
```

기존 서버가 실행 중이면 해당 터미널에서 Ctrl+C 후 위 명령을 다시 실행한다. 이번 작업에서는 사용자의 실행 중 서버를 임의 종료하지 않았다.
